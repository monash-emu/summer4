### The five-site rule (WP13, WP14)

A new `RateOps` node must be wired in five places or it fails silently:

| Site | File | Failure if missed |
|---|---|---|
| evaluator | `register_rate_eval` or `_eval_rate` in `flows/compiled.py` | `TypeError: Unsupported rate expression` |
| `_flow_refs` | `flows/rates.py` | topo-sort silently misorders flows |
| `_field_paths` | `flows/rates.py` | `computed_paths` silently incomplete; params not validated |
| `_rate_bytes` | `flows/rates.py` | **two distinct nodes collide in the jit cache** |
| `__all__` | `flows/__init__.py`, `summer4/__init__.py` | not importable |

Add an explicit `case` in `_flow_refs` and `_field_paths` for every new node
that recurses into children; the `case _` fallback returns `set()` and hides
missing recursion.

## WP13 — Rate-tree math and tabular time series (core)

**Closes:** `KI2` `KI6` `KI10` `KI11` `TM3` `TM4`.

### 13.1 `feat/rate-math` — math nodes

The rate tree has only `BinOp` add/sub/mul/div. The originals use `jnp.tanh`,
`jnp.abs`, `jnp.clip`, `jnp.log`, `jnp.exp`, `jnp.max`, and `N ** exp`. Today
each forces a `Transform` or a `derived_fn`.

Add to `src/summer4/flows/rates.py`:

```python
@dataclass(frozen=True, slots=True)
class UnaryOp(RateOps):
    op: Literal["neg", "exp", "log", "abs", "tanh", "sqrt", "floor"]
    arg: RateOps

# BinOp.op gains "pow", "maximum", "minimum"
def clip(x, lo=None, hi=None) -> RateOps: ...   # sugar over maximum/minimum
```

- `RateOps` gains `__pow__`, `__rpow__`, `__neg__`, `__abs__`; module functions
  `exp`, `log`, `tanh`, `sqrt`, `floor`, `maximum`, `minimum`, `clip` are
  exported from `summer4.flows` and `summer4`.
- **Shape semantics** follow `BinOp` exactly (scalar / per-compartment /
  `GroupedRate` broadcasting), so `Reduce(...) ** Param("exp")` yields a
  `GroupedRate`. Add the `pow` case to `GroupedRate`'s arithmetic in
  `flows/compiled.py`.
- One evaluator dispatch table keyed on `op`; no Python branching on values.
- `_rate_bytes`: `b"unary:" + op + child` and `b"binop:" + op + ...`.

**Tests — `tests/test_rate_math.py` (new):** each op against `jnp` on scalars,
per-compartment arrays and `GroupedRate`; gradients through `log`, `pow`
(exponent as `Param`), `maximum`; `floor` has zero gradient and does not break
`jax.grad`; digest distinctness (`exp(x)` vs `log(x)`); the tb_macro triangular
seed `clip(h * (1 - abs(Time() - p) / w), 0)` and tanh scale-up written as rate
trees match the original `utils.py` functions at 50 times.

### 13.2 `feat/table-interp` — vector-valued tables and `Lookup`

`Interp` is scalar. Kiribati interpolates eight per-age death-rate series
(`demographic_tools.get_death_rates_by_age`), and a per-age treatment-outcome
function built from them. As scalar `Interp` trees that is 8 × ~150 knot nodes.

**`Data.table`** — `src/summer4/data.py`:

```python
Data.table(times: ArrayLike, values: ArrayLike | DataFrame, *, over: Property,
           columns: Sequence[str] | None = None) -> TableData
TableData.interp(kind="linear"|"sigmoidal"|"step", arg=Time(), sharpness=1.0) -> TableInterp
```

`TableInterp(RateOps)` holds a `(T,)` knot array and a `(T, K)` value array as
`ArrayConst`, plus the property. It evaluates with **one** batched `jnp.interp`
(vmapped over columns) or the batched sigmoidal/step evaluator, returning a
`GroupedRate` over `over`. Columns must equal `over.traits` in order; raise
naming the mismatch. Check with `jax.make_jaxpr` that equation count is
independent of `T` and `K`.

**`Lookup`** — gather a row of an array carried in params, for things
precomputed once per run:

```python
Lookup(table: FieldRef, index: RateOps, *, clamp: bool = True)
```

`index` is typically `floor(Time() - 1850.0)`. Evaluates to
`table[clip(int(index), 0, len-1)]` with `jnp.take`. A result of shape `(K, K)`
is valid wherever `MixingMatrix(matrix=...)` accepts an expression, which closes
`KI6`: the Kiribati port computes a `(n_years, 8, 8)` stack from
`(bg_mixing, a_spread, pc_strength)` once per likelihood evaluation and the
vector field only gathers a row.

**Tests — `tests/test_table_interp.py` (new):** table interp equals K scalar
`Interp`s; clamping outside range; `GroupedRate` broadcasting into a flow over
`age`; `Lookup` equals direct indexing, is differentiable w.r.t. the table, and
inside `MixingMatrix` reproduces a hand-written `derived_fn` FOI; jaxpr size
independent of `T`.

### 13.3 `feat/ageing-sugar` — `TraitChain.from_breakpoints`

```python
TraitChain.from_breakpoints(age: Property, *, unit: float = 1.0) -> TraitChain
```

Traits must parse as numeric lower bounds (`"0"`, `"3"`, `"15"`); pairs are
consecutive traits and rates are `1 / (width * unit)`. The last band has no
outgoing edge. Raise if a trait does not parse or bounds are not increasing.
This is sugar: the test asserts equal digests with the hand-written chain.
`S6` stays `partial` in the API ledger (a bundled `AgeStratification` class
remains a rejected shape); only `KI2` and `TM3` close.

**Notebook for 13.1–13.3:** new `examples/notebooks/10-rate-math-and-tables.ipynb`
— tb_macro's seed and detection functions as rate trees; a per-age death table
from a small DataFrame; a yearly matrix via `Lookup`; ageing from breakpoints.
**User gate.**

### 3a. The object — `src/summer4/flows/initial.py` (new)

```python
@dataclass(frozen=True, slots=True)
class InitialPopulation:
    base: Mapping[Selector, RateOps | float]          # absolute counts
    splits: Mapping[Property, Mapping[str, RateOps | float]] = {}
    default: Literal["even"] = "even"
```

Semantics, matching summer3 `build_istate` and summer2's population split:

1. Each `base` entry places an absolute count, divided among the compartments its
   selector matches.
2. For each property in `splits`, compartments carrying that property are
   multiplied by the named proportion. Proportions may be `Param`s or expressions
   (Kiribati's `reachable_pop_frac`). Validation of summing to 1 happens at
   evaluation, reported through the result's solver status rather than a Python
   branch on a tracer.
3. Any property on a matched compartment that is neither selected in `base` nor
   named in `splits` is divided **evenly among compartments that carry it** — the
   ragged-aware rule. A compartment without the property (e.g. `treatment` under a
   `clinical` stratification on `active` only) is not divided.

Computed by gathers over constant index arrays built at compile time (reuse the
`parent_row` idea from `docs/user/06-immutability-and-provenance`), then one
traced multiply per split.

### 3b. The API

- `CompiledModel.initial_state(params, init: InitialPopulation) -> PropertyData`,
  traceable, usable inside a loss.
- `FlowModel.set_initial_population(base, splits=...)` stores the declarative
  object; `compile()` carries it; `run(params, y0=None, ...)` then builds `y0`
  from it. Equal-digest test against passing `initial_state(...)` explicitly.
- `L5` `get_initial_population`: `CompiledModel.initial_state` is it.

### 3c. Tests — `tests/test_initial_population.py` (new)

seeded single compartment (`clin_inf` seed) plus a parameterised reachability

## WP14 — Generalised force of infection (`summer4.epi`)

**Closes:** `KI4` `KI5` `TM5`.

### 14a. `kind="generalised"` — `src/summer4/epi/infection.py`

summer2gen (`summer2/runner/jax/model_impl.py:get_force_of_infection`) computes,
per mixing category `g`:

```
infection_generalised = M @ (I_w[g] / N[g] ** exponent)
```

where `I_w` is infectiousness-weighted infectious population and `exponent` is a
model parameter (`infection_pop_scale`). tb_macro's `infect_process` is the same
with `M = ones` and unweighted `I`.

Add `exponent: RateOps | float | None = None` to `ForceOfInfection`, and
`kind="generalised"` which evaluates `i_grp / n_grp ** exponent` with the WP13
`pow`. Raise if `kind="generalised"` without `exponent`, or `exponent` with any
other kind. `"frequency"` must remain bit-identical to generalised with
`exponent=1.0`; `"density"` to `exponent=0.0` — test both.

The custom callable `kind` stays as is (no params); document that parameterised
shapes go through `kind="generalised"` or rate-tree arithmetic on `Reduce`.

### 14b. Compartment-level infectiousness

Today `infectiousness=` keys only on traits of `group_by`. Kiribati weights by
**compartment × age**: `rel_infectiousness_lowinf`, `rel_infectiousness_subclin`,
and zero below age 15.

Accept `infectiousness: Sequence[tuple[Selector, RateOps | float]]`, applied
multiplicatively **per compartment before** the group sum (`Reduce` over a
weighted state). Keep the existing group-trait mapping as sugar that converts to
`(group_by[trait], w)` pairs; equal-digest test. `normalize_infectiousness`
applies to the effective per-group weight as today. Default for this form is
`None` (summer2 does not normalise).

### 14c. `adjust=` on `EpiModel` infection flows; generalised builder

- `EpiModel.add_infection_frequency_flow`, `add_infection_density_flow` gain
  `adjust=` passed through to `TransitionFlow`.
- `EpiModel.add_infection_generalised_flow(name, source, dest, contact_rate, *,
  exponent, infectious=None, group_by=None, mixing=None, adjust=None)`.
- Equal-digest tests against the declarative path for each.

### 14d. Tests — `tests/test_epi_generalised.py` (new)

Parity with summer2gen's formula on a fixed 3-age state with a non-trivial `M`
and weights (hard-coded expected vector); gradient w.r.t. `exponent`; mixing over
age only while a second property (reachability) is present; compartment ×
age infectiousness with zero for children; `Lookup`-driven time-varying `M`.

### 14e. Notebook

## WP15 — Output algebra (`summer4.results`, jit-traceable)

**Closes:** `KI13` `KI14` `KI15` `KI16` `KI17`. Corrects `D5`'s note.

Kiribati's `outputs.py` requests ~150 summer2 derived outputs: compartment sums
by age and reachability, aggregates over age lists, flow outputs by source
strata summed over several flows, per-capita and percentage ratios, products with
parameters (`prev_se_*` sensitivities), and cumulative sums from 2026. Every
operation below must work **inside `jit`**: index work at trace time, gathers and
arithmetic traced.

### 15a. `Trace` arithmetic — `src/summer4/results/trace.py`

`Trace` gains `__add__ __sub__ __mul__ __truediv__ __neg__` and reflected forms,
with:

- `Trace ∘ Trace` — requires identical time axes (raise otherwise, naming both)
  and broadcastable dims: equal dims, or one side has fewer (e.g. per-age ÷
  total). Dims are aligned by name at trace time.
- `Trace ∘ scalar` and `Trace ∘ jax array` (a parameter from the params pytree
  inside the loss).
- The result's `dims` are the broadcast dims; `values` stays `PropertyData` when
  both sides share a `pmap`, otherwise a raw array.

### 15b. Windowed cumulative, midpoint, multi-flow

- `Trace.cumulative(*, start=None, end=None)` — zeros before `start`, running sum
  from the first save point `>= start`. This is summer2's
  `request_cumulative_output(start_time=)` semantics (it requires `start` to be a
  save time; do the same and raise otherwise).
- `Trace.midpoint()` — `out[0] = f[0]`, `out[i] = (f[i] + f[i-1]) / 2`, summer2's
  default flow-output post-processing (`raw_results=False`). Document that it is a
  parity convention, not the exact incidence of
  `futureplans/state-ledgers-incidence.md`.
- `FlowMass(flow: str | tuple[str, ...], ...)` — several flows summed per saved
  time after their own `where`/`sum_over`. All named flows must share the
  selected dims; raise otherwise.

### 15c. `OutputSet` — declarative named outputs

```python
outputs = OutputSet()
outputs["population"] = Compartments()
outputs["populationXage_15+"] = Compartments(where=age[AGES_15_PLUS]).total()
outputs["tb_incidence"] = FlowMass(("progression_lowinf", "progression_inf")).midpoint()
outputs["tb_incidence_per100k"] = 1e5 * outputs.ref("tb_incidence") / outputs.ref("population")
outputs["cum_tb_incidence"] = outputs.ref("tb_incidence").cumulative(start=2026.0)
outputs["tst_pos_incipient"] = outputs.ref("prev_incipient") * Param("prev_se_incipient_tst")
```

- Leaves are save specs (`Compartments`, `FlowMass`, `ComputedValue`, …) with
  chained post-ops; interior nodes are an expression DAG over `outputs.ref(name)`
  and `Param`/constants. Cycles raise.
- `outputs.plan(base: SavePlan | None) -> SavePlan` contributes only the leaves
  (deduplicated by spec equality), merging with `TargetSet.plan`.
- `outputs.evaluate(result, params) -> Result` computes every named output as a
  `Trace`, traceable.
- `Result.to_frame(names=None, *, shape="wide"|"long", backend="pandas"|"polars")`
  — host-side; wide has a time index and one column per scalar trace, long adds
  dim columns. Needs the `frames` extra (WP12).
- A name ending up unsaved (`save_results=False` in summer2) is just not passed
  to `to_frame`; no flag needed.

## WP16 — TB-scale verification and solver safety

**Closes:** `KI22`.

No benchmark measures model construction or solve cost beyond the taxonomy
(`docs/dev/performance.ipynb` says so).

### 16a. Benchmark — `benchmarks/test_bench_tb_scale.py`

A synthetic model with Kiribati's shape and no Kiribati data: 10 states × 8 age
bands × 2 reachability = 160 compartments; ~40 named flows including a
generalised FOI over age with a `Lookup` mixing stack, per-age table death rates,
recycling deaths, stratum births and a `TraitChain.from_breakpoints` ageing;
1850–2035 yearly saves via an `OutputSet` of ~150 outputs. Record, for `euler`
and `dopri5`: compile time, `make_jaxpr` equation count of the vector field and
of `run`, wall time per run, and `vmap` over 64 parameter sets. Add a
`benchmarks/README` table of the numbers; they are the baseline for future
regressions.

### 16b. Solver failure must be visible

diffrax runs with `throw=False` and `max_steps=4096` (`solvers/diffrax_backend.py`).
A 185-year run that exceeds it returns silently wrong trajectories.

- `SolverInfo.ok` (a traced bool property, `result_code == 0`; always true for
  Euler); `run(..., throw=None)`
  passes through to diffrax when a bool is given.
- When `max_steps` is `None`, derive a default from `(t1 - t0) / dt` with headroom
  instead of 4096.
- WP10 uses `ok` to return `-inf` log-likelihood.

## WP10 — Calibration (`summer4.epi.calibration`)

**Closes:** `KI18` `KI19` `KI20` `KI21` `TM8`. **Unblocks:** textbook 20.

Probabilistic likelihoods were deliberately left out of WP11; `Target.dispersion`
is declared and unconsumed (`results/targets.py`). This package consumes it. It
lives in `summer4.epi` (a calibration workflow is epidemiological per the
separation rule); numpyro and optax are the `calibration` extra.

### 10.1 `feat/epi-priors-likelihoods`

- **Priors** — `Uniform(lo, hi)`, `Normal`, `LogNormal`, `TruncatedNormal`,
  `Beta`, `Gamma`: frozen dataclasses naming a parameter, each with
  `.to_numpyro()` and bounds for unconstrained transforms. Build from a table:
  `priors_from_frame(df, name_col, dist_col, p1_col, p2_col)` covers Kiribati's
  `parameters.xlsx` "constant" sheet.
- **Likelihoods** — `Normal(sd)`, `Poisson()`, `NegativeBinomial(dispersion)`,
  set on `Target(..., likelihood=...)`. `sd` may be a float, a `Param`, or a
  prior (Kiribati's `mixing_dist_sd ~ Uniform(5, 20)` on
  `mixing_matrix_distance`); a prior-valued `sd` becomes a sampled site.
  Helper `Normal.from_tolerance(data, tol_pct)` reproduces
  `get_normal_target`'s `sd = tol/1.96 * mean`.
- `TargetSet.log_likelihood(result, params) -> scalar`, traceable, summing
  `likelihood.log_prob(observed | predicted)`.

### 10.2 `feat/epi-sampling`

```python
bm = BayesianModel(
    compiled, fixed_params, priors, targets,
    outputs=OutputSet | None, init=InitialPopulation | None,
    run_kwargs=dict(t0=..., t1=..., dt=..., solver="dopri5", rtol=..., atol=...),
    preprocess=Callable[[params], params] | None,   # e.g. build the yearly mixing stack
)
bm.log_density(unconstrained)            # jit-able
bm.find_map(init=None, steps=..., optimizer=optax.adam(...)) -> dict
bm.sample(kind="nuts"|"aies"|"ess", num_warmup, num_samples, num_chains, seed) -> arviz.InferenceData
```

- The numpyro model samples priors, applies `preprocess`, runs, evaluates
  `outputs` then `targets.log_likelihood`, and adds `numpyro.factor`. When
  `result.solver.ok` is false the factor is `-inf`.
- `kind="aies"` / `"ess"` are numpyro's ensemble samplers — the gradient-free
  replacement for pymc `DEMetropolisZ` the Kiribati analysis used. `"nuts"` is
  the default where the model is differentiable.
- Chains run with `chain_method="vectorized"` by default so one compiled program
  serves all chains.

### 10.3 `feat/epi-posterior-runs`

```python
runs = bm.posterior_runs(idata, n=1000, burn_in=..., seed=...,
                         scenarios={"baseline": None, "scenario_3": Scenario(params=..., model=...)},
                         batch_size=64)
runs.quantiles(q=(0.025, 0.25, 0.5, 0.75, 0.975)) -> {scenario: DataFrame}
runs.differences(ref="baseline", outputs={"TB_averted": "cum_tb_incidence"}, at=2035.0,
                 relative=True, q=...) -> {scenario: DataFrame}
```

- Batched with `jax.lax.map` over `vmap`ped chunks of `batch_size` so memory is
  bounded; a scenario may swap the compiled model (screening flows added) as well
  as params.
- Quantile frames: time index, columns `(output, quantile)` with quantile labels
  as strings — the parquet-compatible schema of Kiribati's `uncertainty_df_*`.
  Difference frames: quantile index, `X` and `X_relative` columns — the schema of
  `diff_quantiles_df_ref_*`.
