# summer4 0.2.0a5

**Tag:** `v0.2.0a5` · **Date:** 2026-09-28 · **Status:** alpha

This release adds **Bayesian calibration** and most of the **composable
calibration workflow**. A model built with summer4 can now be given priors and
target likelihoods, calibrated by optimisation or MCMC, and run forward under
posterior scenarios — and each calibration stage is a separate piece that
works on the underlying library's own objects (numpyro, optax, evosax).

## Install

```toml
[pypi-dependencies]
summer4 = { git = "https://github.com/monash-emu/summer4.git", tag = "v0.2.0a5", extras = ["calibration", "pandas", "frames"] }
```

```bash
pip install "summer4[calibration,pandas,frames] @ git+https://github.com/monash-emu/summer4.git@v0.2.0a5"
```

Add the `gradient-free` extra for `wf.CMAES`. See
{doc}`../getting-started/installation` for extras and platforms.

## Headline: Bayesian calibration (WP10)

| Capability | How |
| --- | --- |
| Named priors | `Uniform`, `Normal`, `LogNormal`, `TruncatedNormal`, `Beta`, `Gamma`; `priors_from_frame` for tables |
| Target likelihoods | `Normal`, `Poisson`, `NegativeBinomial`, with prior- or `Param`-valued scales; `TargetSet.log_likelihood` traces under `jax.jit` |
| Posterior | `BayesianModel`: `log_density`, `find_map`, `sample` (NUTS / AIES / ESS / SA → arviz) |
| Scenarios | `BayesianModel.posterior_runs` with `Scenario`: per-draw samples, quantiles, differences |

This closes the Kiribati and tb_macro calibration rows (`KI18`–`KI21`, `TM8`)
in {doc}`../evaluation/tb-ports`.

## Headline: the calibration workflow (WP19, steps 24–27)

`from summer4.epi.calibration import workflow as wf`:

| Stage | Pieces |
| --- | --- |
| Design | `wf.lhs`, `wf.prior_draws`, batched `wf.evaluate`, `Candidates.best` / `save` / `load` |
| Optimise | `wf.optimize` with `wf.Optax` + `wf.AutoTune`, or gradient-free `wf.CMAES` |
| Sample | numpyro `MCMC` built by you, seeded with `Candidates.init_params`; `wf.warmup_until` + `wf.WarmupRule` grow NUTS warmup until it is good; `wf.sample_until` + `wf.StopRule` sample in chunks to a stop rule and return a resumable `wf.MCMCRun`; `wf.replay` re-applies a rule to existing draws |
| One call | `wf.run_mcmc` — documented and tested as exactly the lines it stands for |

The ledger's workflow block reads 9 of 11; sampled-output plots (step 28) are
next. Composability is now a stated project goal (see `AGENTS.md`).

## Known issues

Every numpyro `MCMC.run`, and so every `wf.sample_until` chunk, pays a full
XLA compile. Prefer large chunks; see `futureplans/mcmc-chunk-recompile.md`.
