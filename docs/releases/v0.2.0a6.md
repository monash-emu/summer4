# summer4 0.2.0a6

**Tag:** `v0.2.0a6` · **Date:** 2026-10-29 · **Status:** alpha

This release starts the **unification of summer4's lazy idioms**: one way to write
rates, derived outputs and anything else computed from a parameter. Its first half
(Phase L, roadmap steps 31–35) lands here as additive bridges, so the spellings that
already work on rates now also work on likelihood scales and derived outputs. The
release also makes solving composable, lets every calibration workflow stage run on
any numpyro model through a `Posterior` protocol, and adds a NUTS tuning stage.

## Headline: lazy-idiom bridges (Phase L, steps 31–35)

| Spelling | Where it now works |
| --- | --- |
| `np.exp(Param("log_k"))`, `Param("a") * 2` | Likelihood scales: `Normal(sd=...)`, `NegativeBinomial(dispersion=...)` |
| `np.exp`, `np.log`, `np.maximum`, `np.clip`, … and `tanh` / `exp` / `maximum` / `minimum` / `clip` | Output expressions (`outputs.ref(...)`); `Param("s") * outputs.ref("x")` no longer raises |
| `defer(f)(outputs.ref("incidence"), Param("delay"))` | A post-solve derived output: summer2's `Function` over `DerivedOutput` |
| `named(fn, "key")` | Every callable hook (`Transform`, `SaveFn`, `derived_fn`, `prepare_fn`, initial-population callables, FOI `kind`). Rebuilding a model with a fresh closure reuses the compiled program |
| `rate_children(expr)` | The one walk over the rate tree. A custom rate node needs only `__rate_children__` and `__rate_bytes__` |

Gate notebook: `examples/notebooks/26-lazy-idiom-bridges.ipynb`. The second half
(Phase M, steps 36–44) makes the rate tree the only expression type and is not in
this tag; the old ways of writing these things all still work.

## Headline: composable solving and calibration

| Area | What landed |
| --- | --- |
| Solving (step 29) | `run(solver=)` takes a backend: `summer4.solvers.Diffrax(solver, stepsize_controller=, adjoint=, event=, progress_meter=)`, `Euler()`, or any `SolverBackend`. Names and `rtol` / `atol` still work. `Result.final_state` / `final_time` continue a run |
| Entry points (step 30) | `wf.optimize` returns a resumable `wf.OptimizeRun` (`.extend`, `.best_params`); `BayesianModel.find_map` and `.sample` are built from the workflow pieces |
| Any posterior (step 46) | Every workflow stage takes a `Posterior`. `NumpyroPosterior(model)` wraps a hand-written numpyro model (hierarchical latents, plates, several likelihoods) |
| NUTS tuning (step 47) | `wf.tune_nuts(post, starts, target_ess=)` picks the mass matrix, tree depth, target acceptance and warm-up length from short pilots; `wf.laplace_metric`, `wf.metric_screen`, `wf.trajectory_screen`, `wf.warmup_until(abort=)` |

Gate notebooks: `23-solve-backends`, `24-calibration-entry-points`,
`28-calibration-custom-posterior`, `29-calibration-nuts-tuning`.

## Breaking changes (alpha)

- `BayesianModel.sample`: `kind=` is replaced by a `kernel` argument (names are
  still accepted), and it returns a `wf.MCMCRun`; use `.idata` for arviz.
- `BayesianModel.find_map` returns a `wf.OptimizeRun`; the old dict is
  `.best_params`.
- `OptimizeResult` is renamed `OptimizeRun`.

## Fixes

- `SavePlan(ts=...)` is the save grid again (a regression in step 29).
- A `FlowRef` inside a `ForceOfInfection` is ordered before the FOI flow; before,
  the model compiled in the wrong order and raised `KeyError`.
- Capture metadata under `TableInterp`, `Lookup` and `Capture` is collected.

## Known issues

- Every numpyro `MCMC.run`, and so every `wf.sample_until` chunk, still pays a
  full XLA compile (`futureplans/mcmc-chunk-recompile.md`).
- Sampled-output plots (roadmap step 28, `CW10`–`CW11`) are not in this tag.
