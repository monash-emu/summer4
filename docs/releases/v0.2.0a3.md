# summer4 0.2.0a3

**Tag:** `v0.2.0a3` · **Date:** 2026-09-21 · **Status:** alpha

This release finishes what a2 started for **repeated solves staying compiled**.
a2 made Diffrax's equinox Modules structurally stable across `run()` calls; a3
stops plain Python `float` parameter leaves from forcing a recompile on every
draw.

```toml

```

## Headline: `prepare()` boxes float params

Equinox treats Python `float` leaves as **static**. A host loop that passes
`{"beta": 0.1}`, then `{"beta": 0.2}`, … therefore looked like a new program on
every draw, even with a2's Module fix. Warm Diffrax solves were seconds, not
milliseconds.

**What changed** (`fix/prepare-box-float-params`, PR #16):

- `CompiledModel.prepare` walks the params pytree and promotes plain `float`
  leaves to floating JAX arrays (float64 when JAX x64 is enabled).
- `int` / `bool` leaves are left alone (indices and flags).
- Boxing runs after optional `prepare_fn`, so user hooks may still return
  Python floats and stay cache-safe.

**What you should see:** the first `compiled.run(...)` with a given save plan
and solver still pays compile cost; later runs with new Python-float parameter
values reuse the compiled program. `examples/notebooks/05-solvers.ipynb` and
`test_diffrax_repeated_run_with_float_params_stays_warm` assert a warm median
under 50 ms across distinct float `beta` draws on the small SIR Euler probe.

Calibration loops and scenario sweeps that pass `{str: float}` dicts are the
intended beneficiaries — no caller-side `jnp.asarray` boxing required.
