# Case studies

The {doc}`user guide <../user/index>` takes one feature per chapter. A case
study does the opposite: it takes one modelling problem and carries it all the
way through, using whatever the library currently offers and saying plainly
where that runs out.

These are written to be read end to end, and to be honest about the parts that
are still hand-written. Each one names the {doc}`coverage ledger
<../evaluation/coverage-ledger>` rows it leans on.
