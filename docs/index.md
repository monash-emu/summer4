# summer4 documentation

**summer4** is a JAX-native compartmental modelling platform under active
development. This release ships **stage 1: the compartment taxonomy** — the
layer that decides *what the compartments are* and *how you talk about them*.

```{admonition} Read this first — scope of the current release
:class: important

The public API of summer4 today is `Property`, `Trait`, `Selector`,
`PropertyMap` and `Stratification`. There is **no model, flow, rate, solver or
derived-output API yet**. Everything on this site that is presented as runnable
code runs against that taxonomy and is executed on every documentation build.

Material from the [summer2 documentation](https://summer2.readthedocs.io) and
the [summer textbook](https://github.com/monash-emu/summer-textbook) that needs
the model layer is **not reproduced as working code**. It is catalogued instead
in {doc}`user/07-from-summer2` and {doc}`textbook/roadmap`.
```

## Quick example

Every compartment in summer4 is a row in an integer code table. You declare the
axes, apply them (optionally to a subset), and query with a selector algebra:

```python
from summer4 import Property, PropertyMap

state = Property("state", ("S", "I", "R"))
age = Property("age", ("0-4", "5-9", "10+"))
severity = Property("severity", ("mild", "severe"))

pmap = (
    PropertyMap.from_property(state)
    .stratify(age)
    .stratify(severity, where=state["I"])
)

pmap.select(state["I"] & age["0-4"])   # int32 indices
pmap.select(severity.absent())         # compartments with no severity axis
pmap.partition(age)                    # {Trait: indices} per age band
```

See {doc}`getting-started/quickstart` for the walkthrough.

## What is missing, in one paragraph

summer4 can describe a stratified compartment space but cannot yet *run* one.
There is no `Model`, no `add_transition_flow` / `add_infection_frequency_flow`
family, no parameter or time-varying-function layer, no ODE solver, no derived
outputs, and no mixing matrices. A flows prototype exists under
`explorations/flows/` — join semantics, lazy rates, flow adjustments and a
`lax.scan` Euler step. It is deliberately outside `src/summer4` and is not a
supported API, but it is real, tested code and is published as two executed
walkthroughs under {doc}`dev/flows/index`. {doc}`user/07-from-summer2` lists the summer2 symbols that have no
equivalent, and {doc}`textbook/roadmap` does the same per textbook chapter.
